# FlaskApp API Documentation

This Flask server is a local frontend-facing API. In the current mock mode it does **not** call the cluster or `cluster_local_manager.py` during HTTP requests. Instead, it reads precomputed backend responses from `results.pkl`.

## Running The Server

From the project root:

```powershell
python src\FlaskApp\flask_app.py
```

Default address:

```text
http://127.0.0.1:5000
```

## Website Frontend

The FlaskApp directory includes a standalone frontend:

```text
src\FlaskApp\api_frontend.html
```

Open it in a browser after starting the Flask server. The page uses the API base URL shown in the top bar, defaulting to:

```text
http://127.0.0.1:5000
```

The frontend has three menu options:

- **All Cases**: retrieve all cases and retrieve a single case's text.
- **Testing**: run the semantic searcher test and the lexical searcher test.
- **Searching**: choose lexical/semantic, sentence/paragraph, and case/text input.

Unsupported combinations, such as semantic sentence search or lexical paragraph search, show placeholder results in the page.

Optional environment variables:

```powershell
$env:FLASK_HOST="127.0.0.1"
$env:FLASK_PORT="5000"
$env:FLASK_DEBUG="1"
$env:MOCK_RESULTS_PATH="C:\Users\Owner\PycharmProjects\LegalAI\results.pkl"
```

## Mock Results File

The API loads mock data from `results.pkl`, generated by the `cluster_local_manager.py` main block.

Lookup order:

1. `MOCK_RESULTS_PATH`, if set
2. `<project-root>\results.pkl`
3. `<project-root>\src\FlaskApp\results.pkl`

If no file is found, API calls return `503`.

The mock file is a dictionary. Important keys include:

```python
"get_all_cases"
"get_case_text(<case_id>)"
"require_paragraphs_embeddings_search_measurer"
"search_paragraph_semantic_by_case(<case_id>)"
"search_paragraph_semantic_by_text(<exact_text>)"
"require_sentences_lexical_search_measure"
"search_sentences_lexical_by_case(<case_id>)"
"search_sentence_lexical_by_text(<exact_text>)"
```

Text-search endpoints require the same exact text that was used when generating the mock key. Use `GET /mock/keys` to inspect available mock keys.

## Utility Endpoints

### Health

```http
GET /health
```

Returns server status and the mock file path.

### List Mock Keys

```http
GET /mock/keys
```

Returns all keys currently available in `results.pkl`.

### Reload Mock File

```http
POST /mock/reload
```

Clears the in-memory cache and reloads `results.pkl` on the next request.

## Case Endpoints

### Get All Cases

```http
GET /cases
GET /get_all_cases
```

Returns the mock value under:

```python
results["get_all_cases"]
```

Expected shape:

```json
[
  ["case_id", ["citation_1", "citation_2"]]
]
```

### Get Case Text

```http
GET /cases/<case_id>
GET /get_case_text/<case_id>
```

Returns the mock value under:

```python
results["get_case_text(<case_id>)"]
```

Expected shape:

```json
["case_id", "case text", ["citation_1"], "test_flag"]
```

## Paragraph Semantic Endpoints

### Search By Case

```http
GET /cases/<case_id>/paragraph-semantic
GET /search_paragraph_semantic_by_case/<case_id>
```

Returns the mock value under:

```python
results["search_paragraph_semantic_by_case(<case_id>)"]
```

Expected shape:

```json
[
  ["candidate_case_id"],
  ["ground_truth_case_id"]
]
```

### Search By Text

```http
POST /paragraph-semantic/search
POST /search_paragraph_semantic_by_text
```

Request body:

```json
{
  "text": "exact text used in the mock file",
  "k": 5,
  "pool_size": 30
}
```

Returns the mock value under:

```python
results["search_paragraph_semantic_by_text(<exact text>)"]
```

## Example Calls

PowerShell:

```powershell
Invoke-RestMethod http://127.0.0.1:5000/health
Invoke-RestMethod http://127.0.0.1:5000/cases
Invoke-RestMethod http://127.0.0.1:5000/cases/000002
```

POST example:

```powershell
Invoke-RestMethod `
  -Method Post `
  -Uri http://127.0.0.1:5000/paragraph-semantic/search `
  -ContentType "application/json" `
  -Body '{"text":"exact text used in the mock file","k":5,"pool_size":30}'
```
